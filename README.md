# 智能部门值班表排班系统

这是一个用于部门值班排班的本地工具。它可以读取人员名单和学生课表 PDF，判断每个人在指定周次、星期和班次是否有空，并辅助完成值班表制作、导出和统计。

公开仓库与发布包只提供程序、匿名说明和虚构人员模板。真实名单、课表、导出表及内部问题清单仅保存在本机；`data/` 和业务 PDF／CSV／Excel 已加入 Git 忽略规则。请勿强制提交这些文件或把真实成员信息写入公开文档。

软件使用 Streamlit 提供网页界面，但运行在本机电脑上。普通用户使用打包后的版本时，不需要安装 Python，也不需要输入命令。

## 主要功能

1. 人员名单导入

   支持导入 Excel 或 CSV 人员名单。名单中可以记录姓名、班级、部门、职务和校区等信息。

2. 课表批量解析

   支持一次上传多份 PDF 课表，也支持选择课表文件夹或填写本机课表文件夹路径。系统会根据 PDF 文件名识别对应学生姓名，支持网格格式和列表格式课表，并处理跨页课程。

3. 空闲人员查询

   可以按周次、星期、班次查询哪些人可以值班。系统会自动排除当前时间段有课的人。

4. 排班制作

   可以在页面中选择需要排班的周次，然后按星期和班次为每个位置选择值班人员。下拉框中只显示当前时间段可用的人，减少排班冲突。

5. 排班规则提示

   系统会结合课表和校区判断人员是否可值班。例如南校区通勤风险会在可用人员筛选时自动生效。PDF 底部的实践课程会按实践周整周不可值班处理。排班下拉框会显示成员的职务、年级和部门，便于操作人自行判断。

6. Excel 导出和导入

   完成排班后可以导出值班表 Excel。也可以把之前导出的排班表重新导入，继续修改或合并。

7. 值班记录统计

   系统会统计每个人的值班次数，并展示详细记录，方便查看工作量分布。

8. 本地自动保存

   导入的人员名单、已解析课表和值班记录会自动保存在本机，下次打开软件会继续使用上次的数据。

## 普通用户使用打包版

打包后的 Windows 版本通常是一个 zip 压缩包，例如：

```text
DutyScheduler-Windows-日期.zip
```

使用步骤如下：

1. 解压 zip 文件。
2. 打开解压后的 `DutyScheduler` 文件夹。
3. 双击 `DutyScheduler.exe`。
4. 稍等几秒，软件会自动打开浏览器页面。
5. 使用过程中不要关闭黑色命令窗口。关闭该窗口会停止软件服务。
6. 不要只复制 `DutyScheduler.exe` 给别人使用，必须保留它旁边的 `_internal` 文件夹。

如果浏览器没有自动打开，可以手动查看黑色命令窗口中显示的网址，并复制到浏览器地址栏打开。

## 开发环境运行

如果你需要在源码环境中运行项目，请先安装依赖：

```bash
pip install -r requirements.txt
```

然后在项目根目录运行：

```bash
streamlit run duty_app.py
```

如果使用项目自带的虚拟环境，可以运行：

```powershell
.\.venv_pack\Scripts\python.exe -m streamlit run duty_app.py
```

## 数据准备

### 人员名单

人员名单建议使用 Excel 文件。推荐使用更详细的中文表头：

```text
序号
姓名
部门
职务
专业班级
年级
校区
```

对应含义如下：

```text
姓名：成员姓名
部门：成员所在部门，用于后续按部门筛选
职务：干事、干部、部长、副部长、主任团等
专业班级：成员所在专业班级
年级：大一、大二、大三等
校区：旗山北校区、旗山南校区等
```

也兼容英文表头：

```text
Name
Class
Department
Role
Campus
```

校区可以填写南校区、北校区、旗山南校区、旗山北校区等常见写法。系统会尽量自动归一化识别。

### 课表 PDF

课表文件必须是可提取文字的 PDF，文件名中需要包含学生姓名。支持以下格式：

- 网格格式：星期一到星期日作为列，课程详情包含 `(3-4节)1-16周/校区:北校区` 等信息。
- 列表格式：每条课程记录包含“星期、节次、课程信息、周数、校区”。

图片或扫描版 PDF，以及只显示课程名称、学分而没有周次的简略课表，不能准确判断空闲时间。导入时会提示失败，对应成员不会进入可排班名单，请重新从教务系统导出包含周次详情的文字版 PDF。

```text
张三(2025-2026-1)课表.pdf
李四-课表.pdf
```

如果人员名单中有某位同学，但没有导入对应课表，系统会提示该同学缺少课表。缺少课表的人默认不参与可用人员筛选，避免误排。

## 使用流程

### 先选择学期

左侧选择学年开始年份及第 1／第 2 学期。例如开始年份 `2026`、第 `1` 学期表示 **2026–2027 学年上学期**，第 `2` 学期表示该学年下学期。名单、课表、排班、次数统计分别保存，切换前先保存正在编辑的排班。默认学期根据当前日期建议，可以手动修改。

如果发现旧版 `data/app_state.json`，系统不会猜测它的学期：先选实际所属学期，点击“将旧数据归入…”；原文件原样保留为 `data/legacy_app_state.json`。当前学期已有文件时禁止覆盖，须先核对旧数据归属。旧版本解析缓存仍需重新导入 PDF。

PDF 学期从正文标题读取，不依据文件名猜测；正文没有可识别学期或不属于当前学期时会显示具体文件和原因。误导入其他学期的 PDF 不会删掉当前学期的有效课表。

### 第一步：数据导入

1. 打开“数据导入”页面。
2. 上传人员名单 Excel 或 CSV，然后点击“导入人员名单”。空名单、重复姓名或重复表头会报错。
3. 上传课表 PDF。可以选择多个 PDF，也可以选择课表文件夹。
4. 等待系统解析完成。
5. 查看顶部的成员／数据就绪／已保存班次数量，核对“待处理的数据”及最近一次课表处理日志。

“旗山校区”等无法区分南北的校区会列出错误提示，对应成员暂不参与排班，课表仍会保留。补全南校区或北校区后重新导入人员名单即可。

课表支持补传：新文件仅更新当前学期对应成员，不清空其他成员的课表。同一批次中同一成员有多份文件会报错，文件名匹配多位成员或未匹配名单也会报错。已知成员的新课表解析失败时，会移除该成员的旧课表结果，避免继续使用可能过期的数据。开始新学期时选择新学期，再导入名单和课表，无需清空其他学期。

课表文件可以手动命名，如 `程序部-张三.pdf`、`张三课表（最新版）.pdf`，无需保留原始导出名称；文件名必须含名单里的完整、准确姓名，且只能确定一位成员。姓名错字、没有姓名或同时含多个成员姓名时会报错。当前没有通过 PDF 内的姓名／学号核实身份，文件名写错成另一位成员仍可能造成误关联。

### 第二步：空闲查询

1. 打开“空闲查询”页面。
2. 选择周次、星期和班次。
3. 根据需要选择部门、职务或校区等筛选条件。
4. 点击查询，查看当前时间段可值班人员。

查询结果下方可以展开“查看不可值班人员及原因”，查看课表冲突、实践周、通勤、校区不明确或缺少有效课表的原因。

### 第三步：排班制作

1. 在左侧“编排范围”中选择需要排班的周次。
2. 打开“排班制作”页面。
3. 选择正在制作的周次。
4. 在每个星期和班次的下拉框中选择值班人员。
5. 点击“保存当前周排班”。
6. 如需继续制作其他周次，在左侧选择对应周次后重复以上步骤。

### 第四步：导出和导入

完成排班后，打开“统计与导出”页面，在顶部“导出与交接”下载当前学期 Excel。周表采用七行三班布局，避免逐天卡片长距离滚动；候选班次与查询班次均显示中文名称及完整时间。

展开“本机保存到指定位置”也可打开 Windows 保存窗口，默认位置是程序目录下的 `值班表` 文件夹。这个窗口在运行程序的电脑上打开；从其他电脑访问时使用浏览器下载。

如果之后需要继续修改，可以上传之前导出的 Excel。系统会先识别导入文件包含哪些周次：

如果这些周次在系统中还没有值班表，系统会直接导入。

如果系统中已经存在相同周次的值班表，页面会提醒操作者，并提供处理选项。可以选择替换系统内已有周次，也可以只导入没有冲突的新周次。选择替换时，系统会先删除对应周次的旧记录，再导入新的记录，避免同一周的新旧值班表同时存在导致统计不准确。

导入值班表时会校验周次、星期、班次和重复位置：周次必须在 1–20 内，一个位置只能有一名成员。完全重复的位置会合并，同一位置出现不同成员时会报错。历史排班可保留，但有课、缺课表、校区不明或人员不在当前名单的记录，会在导出/导入区域显示冲突或未校验提示。

### 第五步：记录统计

打开“统计与导出”页面，可以查看当前学期每个人的已排班次数、可展开的分布图和详细记录，包含名单里 0 次的成员。一个已保存班次计 1 次，同一天两个班次计 2 次；修改同一周会替换该周记录，不因重复保存增加次数。这是安排次数，尚未记录实际出勤或请假，不会自动均衡排班。

删除课表、清空名单／课表／排班的操作收在“数据准备”的“数据管理：删除课表与清空数据”折叠区。Excel 导入会先显示周次，再明确选择导入、替换或跳过；导入替换和清空记录会重置排班页旧选项，避免把旧人选重新保存。

导出的 Excel 在“学期信息”工作表保存学期标识，文件名也带学期前缀。跨学期导入会被拒绝；旧 Excel 无标识时，需要在页面确认其属于当前学期，再进行导入。

## 数据保存位置

软件会自动把数据保存到项目或软件目录下：

```text

```

如果使用打包版，数据会保存在解压后的 `DutyScheduler` 文件夹内。移动整个文件夹时，数据也会一起移动。

如果需要重新开始，可以在“数据导入”页面底部的“当前学期数据管理”区域清空名单、课表、排班记录或当前学期全部数据；其他学期和旧数据备份不受影响。

### 从旧版升级

旧版仅解析列表课表，可能把网格课表保存成空课表或只含实践周的课表。新版不会继续使用这些缓存，会提示重新导入原始 PDF；人员名单和已保存值班记录会保留。历史排班中的不可用人员会显示警告，调整冲突后才能保存。

具体排班规则为：上午班对应第 3–4 节，下午一班对应第 5–6 节，下午二班对应第 7–8 节；有课则不可值班。南校区成员当天第 7–8 节有课时，不可值下午一班；北校区成员不受这条通勤限制。实践课程所在周整周不可值班。

通勤判断使用人员名单中的校区，未按每门课的校区或实际通勤时长计算。系统不自动平衡值班次数、不限制同一人一天多班、不按职务/年级规定组合；每个位置目前只支持一人。更完整的规则和检查结果见 `SYSTEM_REVIEW.md`。

## 常见问题

### 为什么某个人在下拉框里找不到？

通常有三种原因：

1. 该同学在这个时间段有课。
2. 该同学缺少课表，系统为了避免误排，把他视为不可值班。
3. 当前班次触发了通勤规则。

可以先到“空闲查询”页面选择相同周次、星期和班次，检查系统筛选结果。

### 为什么上传课表后显示找不到对应人员？

请检查 PDF 文件名是否包含人员名单中的姓名。系统主要通过文件名匹配姓名。

### 为什么别人电脑上不能只运行 exe？

这个软件依赖 `_internal` 文件夹中的运行环境和第三方库。必须把整个 `DutyScheduler` 文件夹一起保留，或者直接发送 zip 发布包。

### 如何清空旧数据？

打开“数据导入”页面，在底部“当前数据管理”区域选择清空人员名单、清空课表、清空排班记录或清空所有数据。

### 打不开软件怎么办？

可以先查看软件旁边的命令窗口是否有错误信息。打包版的错误日志通常会写入：

```text
%LOCALAPPDATA%\DutyScheduler\DutyScheduler.log
```

把日志内容发给开发者，通常可以更快定位问题。
